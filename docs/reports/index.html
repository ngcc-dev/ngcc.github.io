Reports

Candidates follow the official type and candidate-number order. A green No report label means that this project has not published an attack report for the candidate; it is not a security assessment or a claim that the candidate is secure. Each issue's classification combines the report's severity with its scope. The status label immediately before each vulnerability records its substantiation: Confirmed, Probable (defect confirmed, attack not yet derived), Lead (heuristic, not instantiated) or Proof gap (the stated proof cannot support the claim; not itself an attack). Click an issue for the full report, including reproduction steps. Design means the finding follows from the submitted construction or specification; implementation means it is in the submitted code, API, or integration rather than the specified construction. Each finding has a stable xxx-yy-z identifier; candidates with multiple findings occupy multiple rows and each row is classified independently.
